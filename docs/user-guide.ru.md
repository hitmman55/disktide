# Руководство пользователя

DiskTide — интерактивная программа для терминала: показывает использование диска, помогает находить данные для очистки и отслеживает изменение размеров каталогов.

## Начало работы

В рабочей копии русской версии выполните:

    uv sync --locked
    DISKTIDE_LANG=ru uv run disktide                  # приветственный экран
    DISKTIDE_LANG=ru uv run disktide ~/projects       # открыть каталог в обзоре
    DISKTIDE_LANG=ru uv run disktide scan --help       # справка по команде

После `uv sync` команда также доступна как `.venv/bin/disktide`. Для выбора английского языка задайте `DISKTIDE_LANG=en`. Без переменной язык определяется по настройкам локали. `DISKTIDE_LANG=ru` работает и при системной локали `C.UTF-8`. Команды установки из PyPI загружают оригинальную версию. См. [установку локализации](../README.ru.md#ustanovka) и [руководство по uv](why-uv.ru.md).

Интерфейс, справка и текстовые отчёты берут язык из окружения при запуске
программы. Для системного журнала службы `disktide watch` задайте
`Environment=DISKTIDE_LANG=ru` в настройках службы. Текст ошибок Ubuntu,
SQLite и других внешних компонентов передаётся в исходном виде. Для
скриптов используйте `--json`. Ключи, значения перечислений и структура
JSON соответствуют англоязычному интерфейсу, а пути передаются как данные.

Установленная команда называется disktide; sizetrail, fsmonitor и fsmonitor-cli сохранены как псевдонимы для совместимости. Пакеты PyPI для Linux и macOS включают необязательное расширение C. В других случаях оно собирается при наличии компилятора. Без него программа использует более медленный модуль на Python. Активный вариант показывает disktide doctor; см. [Модуль сканера](#modul-skanera).

Приветственный экран предлагает текущий каталог, путь по умолчанию, последний посещённый путь и недавние пути сканирования и наблюдения. Введите путь или выбирайте подсказки стрелками вверх и вниз. Стрелка вправо принимает подсказку, Enter открывает путь. Флажок «Сохранить как путь по умолчанию» запоминает выбор. По умолчанию пути хранятся отдельно для каждого имени компьютера. `hostname_aware_paths = false` отключает это.

Переданный в командной строке каталог открывается без приветственного экрана и становится последним посещённым. Неверный первый аргумент (не подкоманда и не каталог) вызывает ошибку использования с кодом 2.

## Терминальный интерфейс (TUI)

Клавиши 1, 2, 3 открывают обзор (Explorer), центр мониторинга (Monitor Center) и обзор файловых систем (FS Overview). Клавиша 4 открывает очистку (Cleanup), если она включена в настройках. Нажмите `?` для списка клавиш текущего экрана или `,` для настроек.

### Обзор (1)

Слева находится дерево файлов. Справа круговая диаграмма (Sunburst, F1) показывает глубину кольцами, карта блоков (Treemap, F2) показывает объём площадью прямоугольников, а «Подробности» (Details, F3) выводят метаданные выбранного элемента.

| Клавиша | Действие |
|---|---|
| ↑ / ↓ | Перемещение по дереву |
| Ctrl+U / Ctrl+D | Сдвиг примерно на четверть видимого дерева |
| ← / → | Свернуть / развернуть узел |
| Enter | Развернуть или свернуть выбранный каталог на месте |
| u / i | Перейти к родителю / открыть каталог |
| s | Сортировка по размеру, имени или времени изменения |
| r | Пересканировать исходный корень (подтвердить y/n; путь указан в запросе) |
| d | Переключить текущее представление / различия снимков |
| [ / ] | Перейти к более новой / старой паре снимков |
| M | Настроить мониторинг каталога |
| y / Y | Скопировать путь / показать путь для ручного выделения |
| t | Переключить метрику: Logical, Allocated, Unique, Files |
| g | Переключить форму sunburst: tiles / disc / fill |

Переключение вида также доступно через F1/F2/F3. В браузере эти клавиши могут перехватываться; используйте Tab для перехода к вкладкам графиков и стрелки влево/вправо либо палитру Ctrl+P. В Current у строки может отображаться мини-график .:-=+*# по сохранённым точкам. Текущий корень сканирования сохраняется отдельно от места навигации: после переходов i команда r повторяет сканирование исходного корня и указывает его в запросе.

Клавиша i по возможности использует уже просканированное дерево. Повторное сканирование требуется, если старых данных недостаточно: при переходе по символической ссылке, в пропущенный политикой каталог или поддерево, ограниченное max_depth.

**Метрики размера.** Клавиша t меняет метрику сразу во всех видах.

| Метрика | Значение |
|---|---|
| Logical | st_size файлов и ссылок — видимый размер содержимого по умолчанию. Собственный st_size каталога не считается. |
| Allocated | st_blocks × 512 у файлов, ссылок и каталогов, включая корень сканирования; каждый путь жёсткой ссылки учитывается. |
| Unique | Занятые блоки, но inode жёсткой ссылки считается один раз. Блоки каталогов всегда учитываются. |
| Files | Число обычных файлов и символических ссылок. |

Каталоги сами занимают место, поэтому Allocated и Unique включают их блоки. При наличии жёстких ссылок du -s соответствует Unique: du также исключает повторный учёт inode. В Unique байты относятся к пути, который первым идёт при лексикографической сортировке. Например, backup сортируется раньше photos, поэтому жёсткая ссылка в backup/photos-2024/ сохраняет байты за backup, а размер photos/ уменьшается. Строка дубликата отмечается как hardlink → ….

Если платформа не поддерживает st_blocks, Allocated/Unique показывают «Unavailable», а не ноль. Каталог, который нельзя прочитать, всё равно вносит собственные блоки в итог и отражается в Coverage; отдельный недоступный каталог не обнуляет результат.

**Различия.** При наличии двух совместимых снимков клавиша d показывает рост, уменьшение, появление и удаление путей. Сравниваются два сохранённых снимка — по умолчанию последние два, например Diff snapshots #30 → #31; текущее сканирование не участвует. Размеры соответствуют более новому снимку. Нажмите d снова, чтобы вернуться к текущим данным. Клавиши [/] листают соседние пары. Недоступный в одном из снимков путь отображается как ≈ partial без направления; для неполного снимка остальные значения получают префикс ≈.

**Символические ссылки** отображаются как имя → цель, но не обходятся. Учитывается размер ссылки, но не цели. Переход по ссылке на каталог клавишей i разрешает её и сканирует реальное расположение.

**Недоступные элементы.** Каталог, который нельзя открыть, помечается красным ⚠. Другие каталоги с недоступными элементами отмечаются ◐ N hidden: это число всех недоступных элементов в каталоге и потомках; закрытый подкаталог считается одним элементом. Значок яркий, если элементы находятся непосредственно в каталоге, и тусклый, если только глубже. Размеры являются нижней оценкой (≥). Подробности (F3) разделяют число элементов в каталоге и ниже по дереву.

Во время сканирования панель показывает этап, число потоков, количество путей, скорость и текущий путь. Через 20 секунд появляется подсказка о настройке потоков через , → Workers и повторном запуске клавишей r; также сообщается, если число потоков ограничено или работа идёт на общем узле.

### Мониторинг (2)

Центр мониторинга хранит настройки наблюдения за изменением размера каталогов.

| Клавиша | Действие |
|---|---|
| n / e | Создать / изменить монитор |
| p | Приостановить / возобновить |
| R / g | Запустить / выполнить полную сверку |
| S | Начать / остановить непрерывный сбор данных |
| i | Закрепить / открепить снимок |
| a / A | Добавить / изменить правило оповещения |
| x / Backspace | Включить, отключить или удалить правило |
| t / r | Обслужить историю / обновить сведения о мониторах |
| Tab | Переключать графики истории (F1–F4) |
| z | Масштабировать график: весь период, половина или четверть |
| Shift+← / Shift+→ | Переместиться по увеличенному графику |

Монитор состоит из сохранённого пути, интервала, метрики, политики сканирования и хранения. Список показывает желаемое состояние, активность и здоровье независимо друг от друга. История: Trend (F1) показывает корень и выбранное поддерево во времени; Diff Map (F2) — treemap базового и целевого снимка; Growth Rings (F3) — sunburst с динамикой; Heatmap (F4) ранжирует повторяющийся рост. На строке снимка b задаёт базовую точку, v — целевую, l возвращает к последней паре. z меняет масштаб на весь период, половину или четверть; Shift+стрелки двигают окно истории. Метки графика: оповещение/аномалия (*), очистка (c), неполная точка (~), закреплённый снимок (o), обычный замер (.).

Переключатель автозапуска сохраняет monitor.auto_start_in_tui; будущий запуск TUI автоматически начнёт сбор данных в переднем плане. Системная служба не устанавливается. В истории есть четыре вида: динамика (F1), treemap различий (F2), кольца роста (F3) и тепловая карта повторяющегося роста (F4). Клавиши b/v задают базовый и целевой снимки, l восстанавливает последние два.

Фоновой службы нет: сканирование выполняется только во время сбора данных в TUI (S или автозапуск) либо пока работает disktide watch. Статус enabled/no-host/... означает, что монитор включён, но не обслуживается процессом; нажмите S или запустите disktide watch --all.

### Обзор файловых систем (3)

Показывает реальные смонтированные файловые системы, тип, носитель (Flash / HDD / RAM / Network), ёмкость, использование и доступную квоту. Блочные устройства и разделы отображаются отдельно, если доступна lsblk.

| Клавиша | Действие |
|---|---|
| Enter | Подробности файловой системы или устройства |
| i | Развернуть / свернуть повторяющиеся строки |
| B | Проверить скорость монтирования после подтверждения |
| r | Обновить |

Псевдофайловые системы скрыты; недоступные источники показывают причину. Образы snap в squashfs только для чтения считаются заполненными на 100%. Повторные bind-монтирования сворачиваются, если файловая система уже показана. Неповторяющееся монтирование остаётся отдельным. В сводке суммируются ёмкость и использование; строки, занимающие менее 1% общей ёмкости, объединяются в «others». Использование считается как занятое / (занятое + доступное), как в df; зарезервированные для root блоки не считаются свободными. При наличии quota показываются квота и использование. Enter открывает подробности устройства, типа, носителя, резерва, inode, размера блока и параметров монтирования. Если доступна lsblk, дерево устройств показывает диски, разделы, RAID-составляющие и точки монтирования; устройство без смонтированной файловой системы отдельно отмечается.

Проверка B после второго нажатия записывает временный файл и читает его обратно. Программа сообщает каталог записи: если корень общей файловой системы недоступен для записи, используется ваш каталог на ней. Записывается максимум 256 MiB и не более четверти доступного места или квоты. Файл удаляется после проверки, в том числе при ошибке; оставшийся файл предыдущего принудительно остановленного теста удаляется перед новой проверкой. max_seconds ограничивает фазы записи и чтения, но не ожидание возврата fsync. Скорость чтения помечается ~, поскольку NFS может игнорировать рекомендацию posix_fadvise и замер тогда отражает кэш клиента. Одновременно допускается одна проверка: вторая отклоняется, чтобы пара потоков, заблокированных в записи, не измеряла друг друга.

### Очистка (4)

Ищет восстанавливаемое место наборами правил для Python, Node, Rust, журналов и временных файлов, метаданных IDE и кэшей контейнеров. По умолчанию отключена; включите её в Настройках (,) → Cleanup Settings.

| Клавиша | Действие |
|---|---|
| Пробел / a | Переключить выбор / выбрать все строки |
| p | Создать и проверить план очистки |
| z | Отменить последний восстанавливаемый план |
| h | История освобождённого места по категориям |
| m | Перейти к карте возраста/размера |

Карта возраста/размера синхронизирована с таблицей: размер и возраст помогают увидеть крупные и давно не менявшиеся кэши. История раздельно показывает оценённое, перемещённое в карантин, окончательно удалённое, фактически освобождённое и восстановленное место. План сначала сохраняется без изменений файловой системы; при применении каждая цель повторно проверяется. Безвозвратное удаление требует отдельного подтверждения DELETE <plan-id>, очистка карантина — PURGE <plan-id>. Команда purge не очищает системную корзину.

Выберите кандидатов, нажмите p и проверьте план. Apply Safe Candidates перемещает объекты в системную корзину или каталог карантина. При необходимости отмените действие клавишей z. Безвозвратное удаление требует ввода DELETE <plan-id>. Перед каждым изменением повторно проверяются идентичность, возраст, соответствие правилу, граница монтирования и защищённые пути; изменившиеся и пропавшие объекты пропускаются.

### Мышь и переназначение клавиш

Мышь включена по умолчанию; отключите её флагом --no-mouse или настройкой mouse = false в [ui]. Щелчок по строке выбирает элемент, щелчок по сектору диаграммы выбирает путь, щелчок по центру sunburst поднимает на уровень выше. Колесо прокручивает дерево и Подробности, наведение показывает имя, размер и долю. Shift+перетаскивание обычно выделяет текст средствами терминала; в hterm Open OnDemand используйте Alt+перетаскивание.

| Жест | Результат |
|---|---|
| Щелчок по строке дерева | Выбрать строку; каталог открывается |
| Щелчок по сектору sunburst или прямоугольнику treemap | Выбрать путь |
| Щелчок по центру sunburst | Перейти на уровень выше |
| Колесо | Прокрутить дерево или Подробности |
| Наведение на диаграмму | Подсказка: имя, размер, доля |
| Shift+перетаскивание | Выделение текста средствами терминала; в hterm Open OnDemand — Alt+перетаскивание |

Нажмите ? для актуальной таблицы клавиш, Ctrl+P ищет команды. В config.toml можно задать раскладку:

    [keys]
    preset = "classic"
    "cleanup.review_plan" = "p"

spine — текущая раскладка; safe — раскладка v0.2.30 с тремя исправлениями (d, u, s); classic — прежняя раскладка v0.2.30. Букву с Shift записывают заглавной, например explorer.setup_monitor = "M"; запись shift+m тоже принимается. Сочетания вроде shift+left и ctrl+shift+m передаются Textual без изменений. Список ? отражает активные привязки. Устаревший ID отключает только одну привязку и вызывает уведомление, не завершая сеанс.

## Команды CLI

Результаты идут в stdout, состояние выполнения — в stderr. --help работает на каждом уровне, --json выдаёт один разбираемый документ.

### doctor

    disktide doctor
    disktide doctor --json
    disktide doctor --check-integrity

Отчёт содержит версии, параметры терминала и цвета, состояние базы, возможности платформы, механизм наблюдения, политику сканирования и активный модуль сканера. Если база не открывается, Проводник использует базу в памяти; Schema помечает её как in-memory fallback. Integrity — PRAGMA quick_check, читающая каждую страницу; при размере базы свыше 256 MiB проверка пропускается, если не задан --check-integrity. Обычный запуск её не выполняет. Отчёт указывает резервную копию data.db.pre-vN.bak и её размер; копию можно удалить после успешной работы новой версии. Блоки Colour и Clipboard диагностируют цвет и доступные способы копирования.

### scan

    disktide scan /path
    disktide scan /path --snapshot
    disktide scan /path -d 5 -w 4
    disktide scan /path --metric allocated
    disktide scan /path --one-file-system --exclude-pseudo
    disktide scan /path --include-snapshots
    disktide scan /path --json

--metric задаёт сортировку и полосы каталогов; сводка всегда показывает три байтовые метрики. Коды выхода: 0 — успех или неполный результат, 1 — ошибка, 2 — неверный ввод, 130 — отмена. Состояние выполнения идёт в stderr, отчёт — в stdout. --max-depth 0 измеряет только корень и отдельно учитывает ограниченное поддерево, отличая его от пустого каталога.

По умолчанию ниже корня пропускаются каталоги снимков: NetApp .snapshot (в CIFS ~snapshot), ZFS .zfs/snapshot при snapdir=visible и VxFS .ckpt. Это полные копии дерева, и их обход повторно посчитал бы те же данные. Они отображаются как исключённая политикой граница. Включите их флагом --include-snapshots или scan.exclude_snapshot_dirs = false. Сам корень никогда не исключается.

Имена файлов — байты, не всегда корректный UTF-8. Текстовый отчёт выводит непечатаемые байты как \xff; JSON заменяет их на U+FFFD (\ufffd), сохраняя корректность документа. Для точных байтов используйте текстовый отчёт.

### compare

    disktide compare latest previous /path
    disktide compare 42 41
    disktide compare --since 7d /path

Первый селектор — целевой, второй — базовый (baseline → target). Допустимы latest, previous, oldest и числовой ID. Политики сканирования должны быть совместимы; иначе код выхода 2. --raw выполняет диагностическое сравнение. --since должен быть допустимым положительным интервалом.

### monitor

```bash
disktide monitor add /data --label data --interval 6h --capture-now
disktide monitor list
disktide monitor status 1
disktide monitor edit 1 --interval 1h --metric allocated
disktide monitor pause 1
disktide monitor resume 1
disktide monitor run 1
disktide monitor reconcile 1
disktide monitor retention 1             # предварительный просмотр
disktide monitor retention 1 --apply     # выполнить обслуживание
disktide monitor pin 42 --label release
disktide monitor unpin 42
disktide monitor remove 1                # архивировать, сохранить историю
```

Команды `add`, `list`, `status`, `edit`, `pause`, `resume`, `run`, `reconcile`, `retention`, `pin`, `unpin` и `remove` управляют сохранёнными мониторами. Вместо числового ID можно использовать метку. `list/status --json` предназначены для сценариев. Путь для создания или изменения должен быть существующим каталогом. `retention` без `--apply` только показывает, что будет сохранено и удалено; применение выполняет обслуживание. `remove` архивирует монитор, не стирая историю.

### alerts

```bash
disktide alerts add 1 /data --size 500GiB
disktide alerts add 1 /data/logs --growth 10GiB --window 24h
disktide alerts add 1 /data --percent 20 --cooldown 6h
disktide alerts add 1 /data --free-space 50GiB --severity critical
disktide alerts add 1 /data --inode-free 100000
disktide alerts add 1 /data/incoming --new-large 4GiB
disktide alerts list 1
disktide alerts check 1
disktide alerts disable RULE_ID
disktide alerts enable RULE_ID
disktide alerts remove RULE_ID
```

`--size` задаёт абсолютный размер, `--growth` — прирост за период `--window`, `--percent` — процент изменения, а `--cooldown` — интервал подавления повторных уведомлений. `--free-space` задаёт порог свободного места и допускает `--severity` (например, `critical`); `--inode-free` задаёт минимум свободных inode; `--new-large` — размер нового крупного элемента. Правила можно перечислить, проверить, отключить, включить и удалить. `alerts check` возвращает `0` (срабатываний нет), `2` (есть не подавленное срабатывание) либо `3` (все срабатывания подавлены).

Пороги проверяются до сохранения; ошибка использования возвращает код 2. Каждый порог размера (`--size`, `--growth`, `--free-space`, `--new-large`) должен быть больше нуля и не превышать 2^63−1 байт. `--percent` должен быть конечным числом больше нуля и не выше 1 000 000. `--inode-free` — конечное число от 0 до 2^63−1. `alerts edit --threshold` выбирает один из трёх вариантов порога, соответствующий типу изменяемого правила.

### watch

    disktide watch /path
    disktide watch /path --interval 1h
    disktide watch /path --events
    disktide watch /path --periodic-only
    disktide watch --monitor 1
    disktide watch --all

Обработчик работает в переднем плане до прерывания или --max-time. Режим auto использует нативные события при наличии поддержки, иначе — периодический опрос. --events требует нативный механизм. PATH должен быть существующим каталогом, иначе команда возвращает код 2. Для долгой работы используйте tmux или пользовательский модуль systemd; пример находится в docs/examples/disktide-watch.service.

### cleanup

    disktide cleanup /path
    disktide cleanup --plan PLAN_ID --apply
    disktide cleanup --plan PLAN_ID --permanent
    disktide cleanup history --by category
    disktide cleanup undo PLAN_OR_ACTION_ID
    disktide cleanup purge PLAN_OR_ACTION_ID
    disktide cleanup quarantine audit /path/.disktide-quarantine
    disktide cleanup quarantine rebuild /path/.disktide-quarantine
    disktide cleanup rules list
    disktide cleanup rules validate /path/to/pack.toml

Первая команда только сохраняет план. --apply перепроверяет цели и перемещает их в корзину или карантин. --permanent необратим и требует подтверждения DELETE <plan-id>. undo и purge возвращают ненулевой код, если объекты не удалось обработать; причины идут в stderr. Пользовательские наборы правил хранятся в ~/.config/disktide/cleanup-rules/. Отключение правила имеет приоритет над явным включением.

## Настройки

Редактируйте ~/.config/disktide/config.toml или откройте Настройки клавишей ,. Путь учитывает XDG_CONFIG_HOME; старые настройки sizetrail/fsmonitor-cli переносятся автоматически. Если нового каталога данных нет, старая база открывается на прежнем месте и мигрирует. Перед миграцией создаётся data.db.pre-v11.bak; удалите её после успешной работы новой версии. Чтобы оставить старую базу нетронутой, до первого запуска переименуйте старый каталог.

Пример конфигурации и все имена параметров:

    [scan]
    max_depth = 10                           # не задавать для неограниченной глубины
    workers = 4                              # не задавать для автоопределения
    # one_file_system = true                 # по умолчанию false
    # exclude_pseudo_filesystems = false     # по умолчанию true
    # exclude_snapshot_dirs = false          # по умолчанию true (.snapshot, .zfs, .ckpt)

    [monitor]
    default_interval = 21600                 # 6 часов, секунды
    database_soft_budget = 2147483648        # 2 GiB
    database_hard_budget = 3221225472        # 3 GiB
    # auto_start_in_tui = true              # по умолчанию false
    event_mode = "auto"                      # auto | events | periodic

    [cleanup]
    # prefer_trash = false                   # по умолчанию true
    quarantine_retention_days = 7            # 7 дней
    quarantine_max_bytes = 10737418240       # 10 GiB
    # disabled_rule_packs = ["node"]        # отключить набор
    # enabled_rule_packs = ["mine"]         # включить opt-in-набор

    [ui]
    color_theme = "disktide"
    default_viz = "sunburst"
    # show_cleanup = true                    # по умолчанию false
    # ring_shape = "disc"                    # по умолчанию tiles
    # mouse = false                          # по умолчанию true
    # cell_aspect = 2.43                     # не указывать для автоопределения
    # color_depth = "truecolor"              # auto (по умолчанию) | truecolor | 256 | 16
    # safe_rendering = true                  # ASCII-only для веб-терминалов
    # live_scan_render = "auto"              # auto | on | off
    # hostname_aware_paths = false           # по умолчанию true

    [keys]
    # preset = "classic"                     # spine (по умолчанию), safe, classic
    # "cleanup.review_plan" = "p"           # переопределить отдельную клавишу

Поля необязательны. Неизвестное значение заменяется настройкой по умолчанию, чтобы файл от новой версии не мешал запуску старой. Неверный тип, например workers = "4" вместо целого workers = 4, является ошибкой использования с указанием секции и ключа (код 2).

Если workers не задан, сканер оценивает путь: 1 поток для прогретого локального хранилища, 2 для вращающегося диска, 8 для сети/FUSE и 16/32/64 при сетевой задержке от 0,5/1/3 мс на элемент. Берётся худшее значение из выборки 64 элементов корня и среднего обмена NFS из /proc/self/mountstats. Расчёт также ограничен долей CPU. В пакетном задании или контейнере учитываются видимые CPU; на личной машине — минутная нагрузка; на общем узле — доступная доля простаивающих CPU с учётом нагрузки и числа пользователей. В среднем сканирование использует около 160 мкс CPU на элемент. Сетевые потоки в основном ждут, локальные заняты работой. При доступной памяти менее 512 MiB сканирование последовательное.

Явный workers пропускает измерение, но ограничивается max(64, 4 × доступные CPU). Превышение ограничивается с предупреждением: оно появляется в stderr, JSON workers.warnings и в TUI. Нулевое и отрицательное значение — ошибка ввода (код 2).

### Ускорение сканирования

Задайте число потоков в одной команде (`disktide -w 32 /mnt/share`), в секции `[scan]` (`workers = 32`) или через Настройки → Workers, затем нажмите `r`. Подсказка показывает автоматический выбор и предел хоста. Дополнительные потоки помогают, если сканирование ждёт хранилище; на прогретом локальном диске почти не ускоряют его.

Измерения `tool/bench_scan.py`, режим raw, нативное чтение, узел с 16 CPU (2026-09-05; время в секундах):

| Дерево | 1 поток | 4 | 8 | 16 | 32 | 64 |
|---|---:|---:|---:|---:|---:|---:|
| Локальный xfs, 88 тыс. каталогов / 888 тыс. файлов, прогретый | 7,9 | 8,6 | 8,3 | 8,7 | 8,2 | — |
| Домашний NFSv4, кэш клиента сброшен | — | — | 16,5 | 14,2 | 13,1 | 12,5 |
| То же дерево NFSv4, кэш клиента прогрет | — | 9,8 | 9,7 | 10,7 | 10,1 | 9,7 |
| NFSv3 sec=krb5p, 1,17 млн каталогов / 4,93 млн файлов, 128 CPU, кэш атрибутов сброшен | — | — | — | 283 | 233 | 229 |

Для последнего сетевого сценария автонастройка выбирает 16 потоков. 32 потока ускорили проход на 18% примерно за одно дополнительное ядро, а 64 не дали выигрыша: время упёрлось в CPU и блокировки планировщика. На NFSv4 16 потоков дали около 15% к автонастройке 8; ещё 10% потребовали 32–64 потока и увеличили системное CPU. На прогретом локальном диске и при прогретом сетевом кэше потоки почти ничего не меняют: сканирование ограничено интерпретатором. Запасной backend на чистом Python может замедлиться от потоков: 20,5–23,8 секунды при 8–16 потоках против 7,9 секунды с одним. Первый обход холодного сетевого дерева может также прогревать кэш сервера; на общем узле число потоков зависит от доступной доли CPU, а не только от задержки хранилища.

### Форма колец

Клавиша g переключает формы sunburst: tiles (по умолчанию) — прямоугольные кольца без калибровки; disc — круглые кольца; fill — прямоугольные кольца на всю панель. Для disc и fill нужно задать точное cell_aspect.

<a id="modul-skanera"></a>
### Модуль сканера

Расширение C читает каталог и измеряет его элементы за один проход, уменьшая накладные расходы Python и ускоряя параллельное сканирование. Оно необязательно. Выпущенные пакеты Linux/macOS включают готовый модуль; установка из исходников собирает его при наличии компилятора. Рабочая копия, установленная pip install -e . или uv sync, также должна его собрать.

Проверить режим можно командой disktide doctor | grep Scanner: native (_scanfast) означает нативный модуль, python fallback — запасной вариант. В JSON это поле platform.scanner. Для одного запуска запасной вариант включается DISKTIDE_ACCEL=0 (также off/no/false). Оба варианта должны возвращать одинаковые деревья. Для сборки нужны cc/gcc/clang и заголовки Python (python3-dev / python3-devel). Одно чтение очень большого каталога нельзя прервать посередине; отмена может задержаться примерно на треть секунды.

### Соотношение сторон символа

Формам disc и fill нужно отношение высоты ячейки терминала к ширине. Обычно оно определяется автоматически. В xterm.js, VS Code, Windows Terminal, mosh и screen часто нет размера в пикселях, поэтому используется 2.0 и круги выглядят немного овальными. Значение задаётся через Настройки → Cell aspect, cell_aspect в [ui] или DISKTIDE_CELL_ASPECT=2.43. disktide doctor показывает активный способ определения.

## Цветовые темы

Шесть тем доступны через Настройки или color_theme: Disktide — тёплый угольный фон; Cold — тёмно-синий с холодной палитрой; Colorblind-safe — Okabe–Ito и различимые оттенки серого; Cyberpunk — индиго и неон; Mono — чёрный и серый; ANSI 16 — собственная палитра терминала. Первые пять оформляют всё окно и проверены на контраст; ANSI 16 использует цвета, заданные терминалом.

## Веб-оболочки и глубина цвета

Open OnDemand сообщает TERM=xterm-16color, JupyterLab — xterm-color, поэтому по умолчанию используется тема ANSI 16. VS Code с xterm-256color и COLORTERM=truecolor поддерживает 24-битный цвет. Оболочки hterm и xterm.js фактически поддерживают RGB, но псевдотерминал может передавать устаревший TERM. Под tmux TERM описывает созданный tmux терминал, а не клиента. DiskTide опрашивает подключённых клиентов и ориентируется на наименее способный.

Глубину можно задать параметром color_depth в [ui] (auto, truecolor, 256, 16) или переменной DISKTIDE_COLOR_DEPTH для одного сеанса. Для tmux можно указать поддержку терминала:

    set -as terminal-features ",xterm-16color:256,RGB"

Затем переподключитесь; tmux list-clients -F '#{client_termname} #{client_termfeatures}' показывает клиент. Вне tmux задайте export COLORTERM=truecolor. disktide doctor показывает переменные окружения и выбранную глубину цвета.

### Символы в браузерном терминале

Шрифт xterm.js может не содержать блочные символы или рисовать их шириной, отличной от терминальной ячейки. DiskTide поэтому закрашивает области цветом фона пробелов: полосы дерева и файловых систем, прогресс, образцы тем, форма tiles и treemap. Для градаций используются ASCII .:-=+*#, график использует точку. В веб-терминале предпочтительна форма tiles; для других форм можно установить моноширинный шрифт с поддержкой рамок, например DejaVu Sans Mono, Cascadia Mono или Menlo. ui.safe_rendering включает ASCII-обозначения для терминалов без надёжной поддержки фоновых цветов и символов.

## Копирование путей

Клавиша y копирует выбранный путь. В терминале запись в буфер часто нельзя подтвердить; уведомление показывает доступный способ.

| Среда | Действие | Подтверждение |
|---|---|---|
| tmux 3.2+ | Буфер tmux disktide через load-buffer -w | Код выхода |
| tmux старше 3.2 | Буфер и OSC 52 через DCS passthrough | Буфер да, пересылка нет |
| Терминал через ssh | OSC 52 | Нет |
| Open OnDemand | OSC 52 через hterm | Нет |
| JupyterLab | OSC 52 отбрасывается xterm.js | Нет; используйте Y |
| Локальная система | pbcopy, wl-copy, xclip или xsel | Код выхода |

Под tmux DiskTide записывает путь в именованный буфер и просит tmux переслать его, учитывая set-clipboard. Буфер можно вставить командой prefix ]. OSC 52 работает в ряде современных терминалов, но не в macOS Terminal.app, старых VTE/GNOME Terminal и JupyterLab. Y открывает путь в окне, где мышь не перехватывается; выделите текст средствами терминала. Shift+перетаскивание обычно выделяет текст, в hterm используйте Alt+перетаскивание. --no-mouse или mouse = false выключает обработку мыши на сеанс.

## Категории типов файлов

Категория определяется расширением; неизвестные расширения серые.

| Категория | Типичные расширения |
|---|---|
| code | py, js, ts, c, cpp, go, rs, rb, sh, css, html |
| docs | pdf, doc, md, txt, json, yaml, toml, xml, lock |
| data | csv, sqlite, parquet, h5, pkl, safetensors |
| media | png, jpg, mp4, wav, svg, gif |
| archive | zip, tar, gz, 7z, rar, zst, deb, iso |
| ephemeral | pyc, so, whl, dll, log, class, o, obj |

Содержимое пересоздаваемых контейнеров (.venv, node_modules, __pycache__ и др.) целиком относится к ephemeral. Каталог окрашивается по преобладающей категории; если явного большинства нет, остаётся нейтральным. Легенда sunburst показывает долю категорий.
