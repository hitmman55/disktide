# Как читать TUI: Проводник, Центр мониторинга и Обзор файловых систем

*Практическое руководство по панелям трёх основных экранов DiskTide и тому, как их читать. Написано для версии v0.3.0.*

В DiskTide три основных экрана, каждому соответствует цифровая клавиша: `1` — Проводник, `2` — Центр мониторинга, `3` — Обзор файловых систем. `4` открывает Очистку, которая по умолчанию выключена. Большинство данных здесь плотнее обычной таблицы: кольца, прямоугольники, однобуквенные метки и цвета, у каждого из которых есть определённый смысл. В этой статье разберём панели по очереди.

Несколько клавиш работают везде: `?` показывает карту клавиш текущего экрана, `,` открывает Настройки, Ctrl+P ищет действие по названию, `q` завершает работу.

Все иллюстрации ниже — настоящие кадры TUI, а не макет: DiskTide работала в tmux в размере 150×46, снимки сохранены с цветом и растеризованы по ячейкам. Поверх экрана добавлены только нумерованные выноски. Пересоздать иллюстрации можно через `tool/gen_blog_shots.py`. Данные в иллюстрациях искусственные: специально подготовленный домашний каталог для Проводника и Центра мониторинга и выдуманный сервер для Обзора файловых систем.

## Домашний каталог на иллюстрациях

Проводник и Мониторинг показывают один синтетический домашний каталог `/tmp/home`. Он устроен так, чтобы четыре метрики размера расходились, а история отражала изменения:

| Путь | Содержимое | Зачем он включён |
|---|---|---|
| `vm/dev-box.qcow2` | Образ диска 512 МиБ, из которых занято 96 МиБ | Разреженный файл: Logical и Allocated дают разные числа |
| `backup/photos-2024/` | Жёсткие ссылки на 160 JPEG в `photos/2024/` | Allocated считает копии дважды, Unique — один раз |
| `private/`, `projects/legacy/secrets/` | Режим доступа 000 | Недоступные каталоги делают сканирование неполным |
| `latest-dataset` | Символическая ссылка на `datasets/climate/` | Ссылки перечисляются, но не обходятся |
| `datasets/`, `models/` | CSV, Parquet, HDF5, safetensors, контрольные точки | Категория data |
| `photos/`, `papers/`, `archives/`, `downloads/` | JPEG, MP4, PDF, tar-архивы, ISO | Категории media, docs и archive |
| `.cache/`, `projects/analysis/.venv/`, `projects/webapp/node_modules/` | Кэши пакетов и зависимости | Пересоздаваемые контейнеры категории ephemeral |

Итого: 1,4 ГиБ логически (989,4 МиБ выделено на диске, 942,2 МиБ уникальных данных), 2356 файлов и 171 каталог.

На `/tmp/home` создан монитор с 34 снимками за 31 день: по одному в день, плюс два дня с несколькими измерениями; последний снимок — 12 сентября 2026 года. За месяц рос журнал сборки (на 250 КиБ в день), каждые три дня добавлялась контрольная точка по 5 МиБ, а в `datasets/climate/raw/` четыре раза появлялось по дюжине CSV. Каталог `node_modules/` появился на восьмой день, сорок фотографий — на двенадцатый, резервный tar-архив размером 25 МиБ — на пятнадцатый; его удалили на двадцать четвёртый. Кэш pip очистили на двадцатый день и восстановили на двадцать седьмой. На двадцать восьмой день образ диска занял ещё 32 МиБ, хотя его логический размер не изменился.

В последний день произошло по одному изменению каждого типа: PDF диссертации вырос на 1,7 МиБ, кэшированную модель удалили, появились Parquet-файл и весь каталог `downloads/`, а `papers/drafts/` удалили. После последнего снимка некоторые файлы изменились ещё раз. Поэтому текущее сканирование немного расходится с последним снимком — это важно для режима Diff.

## Проводник: диаграмма sunburst (F1)

Команда `disktide PATH` сканирует каталог и открывает Проводник. Если запустить `disktide` без пути, появится приветственный экран. Слева — отсортированное по выбранной метрике дерево каталогов; справа — одна из трёх вкладок: Sunburst, Treemap и Подробности.

Sunburst — вид по умолчанию. Его смысл можно выразить одной фразой: **одно кольцо на каждый уровень глубины, длина сектора показывает долю родительского элемента, цвет — тип файла.**

![Проводник для /tmp/home сразу после сканирования. Слева в дереве первым стоит vm/ размером 512,0 МиБ (36,6%); в каждой строке есть шестисимвольный график истории, полоса доли и процент. У projects/ значок «1 hidden», у private/ красное предупреждение. Справа sunburst формы tiles: прямоугольные кольца вокруг центра «home 1.4 GiB», серый сектор vm/ занимает треть второго кольца; легенда: other 37%, data 28%, media 15%, ephemeral 10%, docs 7%, archive 3%. Двенадцать выносок отмечают описанные элементы.](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/explorer-sunburst.png)

*Проводник сразу после сканирования: курсор на корне, метрика Logical, форма колец `tiles`.*

1. **Хлебные крошки.** Путь текущего корня. Длинный путь сворачивается в середине, сохраняя видимым каталог, в котором вы находитесь. `◐` означает, что часть дерева не удалось прочитать.
2. **Индикатор.** Порядок сортировки, метрика и режим. По умолчанию сортировка идёт по размеру активной метрики (поэтому указано `Sort: Logical`); клавиша `s` переключает сортировку по имени и времени изменения. `t` меняет метрику. В режиме Current показано это сканирование, в Diff — выбранная пара снимков.
3. **Мини-график истории.** Размер этого пути в шести последних снимках корня, символами от `.:-=+*#`, от минимального значения пути к максимальному. `======` означает отсутствие изменений. Пустые клетки слева относятся ко времени до появления пути. Столбец появляется, когда у корня есть история; `tmp/` — журнал, который растёт каждый день. Справа от строки находятся полоса и процент доли корня по выбранной метрике. Все полосы начинаются в одном столбце и используют общую шкалу. Если для полосы не осталось места из-за длинного имени, процент сохраняется, а полоса скрывается.
4. **`◐ N hidden`.** N элементов в этой строке или ниже не удалось прочитать; поэтому показанные размеры являются нижней оценкой. Значок яркий, если часть этих элементов находится прямо в каталоге, и тусклый, если все они глубже.
5. **`⚠`.** Каталог вообще не удалось открыть. Показано 0 Bytes не потому, что каталог пустой, а потому что его содержимое не удалось посчитать.
6. **Вкладки видов.** `F1` — Sunburst, `F2` — Treemap, `F3` — Подробности. В браузере F1/F3 могут перехватываться: переключитесь на вкладки клавишей Tab и используйте ←/→ либо Ctrl+P.
7. **Центр.** Текущий корень и его размер по активной метрике. Щелчок по нему поднимает на один уровень, как `u`.
8. **Внутреннее кольцо.** Сам корень; оно всегда заполнено полностью. При наведении подсказка говорит `home (this root)` и сообщает, что щелчок поднимет выше.
9. **Второе кольцо.** Прямые потомки корня. Длина сектора равна доле: `vm/` содержит 36,6% байтов, поэтому серый сектор занимает чуть больше трети кольца. Где хватает места, соседние сектора разделены тонкими тёмными границами.
10. **Внешние кольца.** Каждое следующее кольцо — уровень дерева глубже; отображается до четырёх уровней ниже корня (во время сканирования — до двух). Файлы тоже получают сектора.
11. **Легенда.** Доля байтов каждой категории под корнем. Она считает байты независимо от выбранной клавишей `t` метрики; подпись `by bytes` это уточняет. Категории меньше 1% объединяются в `<1%`.
12. **Нижняя строка.** Повседневные клавиши; `?` показывает их полный список.

### Цвет: тип файла

Категория файла определяется расширением:

| Категория | Примеры расширений |
|---|---|
| code | py, js, ts, c, cpp, go, rs, sh, html, css, ipynb |
| docs | pdf, md, txt, tex, json, yaml, toml, xml, lock |
| data | csv, parquet, h5, npy, pkl, sqlite, pt, safetensors, onnx |
| media | png, jpg, svg, gif, mp4, mov, wav, flac |
| archive | zip, tar, gz, xz, zst, 7z, iso, deb, rpm |
| ephemeral | pyc, so, o, whl, class, log, out |
| other | Всё остальное, например образ диска .qcow2 |

Поверх правил расширений действуют ещё два правила.

- Всё содержимое пересоздаваемых контейнеров (`.venv`, `venv`, `node_modules`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.tox`, `.nox`, `.eggs`, `.cache`) относится к ephemeral независимо от расширения. Файлы `.py` внутри виртуального окружения — установленные зависимости, а не ваш исходный код.
- Каталог получает цвет категории, в которой содержится больше всего байтов. Для каталогов используются более тёмные и менее насыщенные оттенки, чем для файлов, чтобы папку не принять за файл. Каталог без явного лидера остаётся серым.

Точные оттенки зависят от темы, которую можно выбрать в Настройках (`,`).

### Наведение и выбор объектов

Диаграмма связана с деревом. Переместите курсор на `datasets/` — его сектор второго кольца станет ярче. Быстрее всего сопоставить секторы и строки, перемещая курсор клавишей ↓. Наведение на сектор показывает имя, размер по активной метрике и долю корня.

![В Проводнике курсор дерева стоит на datasets/. Его сектор второго кольца sunburst подсвечен; всплывающая подсказка над ним: «datasets, 280.3 MiB · 20%».](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/sunburst-hover.png)

*Курсор на datasets/, указатель мыши над сектором: 280,3 МиБ, 20% корня.*

Клавиша `i` открывает выбранный каталог; он становится корнем дерева, диаграммы и хлебных крошек. Используется дерево уже выполненного сканирования. Повторное сканирование нужно только когда дерево не может дать ответ: цель символической ссылки, каталог, пропущенный политикой сканирования, или поддерево, ограниченное `max_depth`. Щелчок по сектору делает то же самое. `u` или щелчок по центру возвращает к родителю.

`Enter` только раскрывает или сворачивает строку под курсором, так же как → и ←. `r` после подтверждения пересканирует исходный корень.

     src="https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/sunburst-root-ring.png" width="49%">

     src="https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/sunburst-drill.png" width="49%">

*Слева: внутреннее кольцо — сам корень. Справа: переход клавишей `i` в datasets/. У него два дочерних каталога с данными, остальные категории объединены в `1 more <1%`.*

### Три формы колец (g)

<img alt="Та же диаграмма sunburst в форме disc: круглые кольца, разделённые лучами от центра; края сглажены."
     src="https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/sunburst-disc.png" width="49%">
<img alt="Та же диаграмма sunburst в форме fill: прямоугольные кольца на всю панель, разделённые лучами; диагональные границы выглядят ступенчатыми."
     src="https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/sunburst-fill.png" width="49%">

*Слева `disc`, справа `fill`.*

Клавиша `g` переключает форму и сохраняет её в config.toml как ring_shape в секции [ui].

- **tiles** (по умолчанию) строит прямоугольные кольца с прямыми границами. Все границы совпадают с границами ячеек, поэтому независимо от шрифта и пропорций символов каждая ячейка имеет сплошной цвет, в том числе в браузерном терминале. Компромисс: потомки сектора располагаются не на луче от центра, а в полосе непосредственно снаружи него.
- **disc** — классическая sunburst: круглые кольца, разделённые лучами и сглаженные символами половинных блоков.
- **fill** сохраняет лучевое деление, но растягивает прямоугольные кольца на панель.

Для disc и fill необходимо знать отношение высоты ячейки терминала к её ширине. Если терминал не сообщает размер в пикселях, DiskTide предполагает 2.0. Настройка Настройки → Cell aspect позволяет переопределить значение.

## Проводник: treemap (F2)

Treemap использует площадь, а не угол. Площадь прямоугольника пропорциональна размеру по активной метрике; элементы раскладываются на три уровня дерева (во время сканирования — на два). Такой вид быстрее колец отвечает на вопрос «что здесь самое большое» и помещает больше подписей. Используются те же категории цветов, но каждый следующий уровень темнее.

![То же домашнее дерево в treemap. Образ dev-box.qcow2 размером 512,0 МиБ занимает верхний левый угол; ниже — datasets/climate и raw размером 185,8 МиБ; справа колонка с photos, models, .cache, papers, backup, projects и archives, у каждого есть заголовок. Восемь выносок отмечают описанные элементы.](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/explorer-treemap.png)

*То же дерево в treemap.*

1. **Заголовок.** Текущий корень; `◐` указывает на неполный результат.
2. **Каталог верхнего уровня** получает заголовок и рамку, а содержимое рисуется внутри.
3. **Глубокий каталог** (например, `llama-mini` в `models`) получает заголовок, если прямоугольник достаточно широкий для имени и достаточно высокий, чтобы выделить отдельную строку.
4. **`… 145 more`.** Слишком мелкие элементы сворачиваются в одну ячейку с количеством и суммарным размером. Здесь в основном так объединено фото-зеркало в `backup/`. Ветка под курсором не сворачивается, даже если очень мала.
5. **Подписанный файл.** Если для имени достаточно места, показываются имя и размер.
6. **Каталог на пределе глубины** (`raw`, три уровня ниже) представлен одной ячейкой с общим размером.
7. **`◐` после имени.** Ниже по дереву есть элементы, которые не удалось прочитать.
8. **Похожие файлы.** Их оттенок слегка чередуется, чтобы десять контрольных точек выглядели отдельными файлами, а не одним блоком.

![Указатель наведён на dev-box.qcow2; подсказка показывает «dev-box.qcow2, 512.0 MiB · 37%».](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/treemap-hover.png)

*Наведение и щелчки работают как в sunburst. Доля в подсказке совпадает с деревом: здесь 37%, в дереве 36,6%.*

## Четыре способа измерения (t)

Клавиша `t` переключает метрику сразу в дереве, сортировке, обеих диаграммах и Подробностях. Каждая метрика отвечает на свой вопрос; один и тот же каталог может ранжироваться совершенно по-разному.

| Метрика | Что учитывает | Значение для этого примера |
|---|---|---|
| Logical | st_size файлов и ссылок: видимые приложению байты. Собственный размер каталога не учитывается. | 1,4 ГиБ; лидирует vm/ с 512,0 МиБ (36,6%). |
| Allocated | st_blocks × 512 каждого файла, ссылки и каталога: блоки на диске; каждый путь жёсткой ссылки считается. | 989,4 МиБ. Разреженный образ уменьшается до 96,0 МиБ, лидирует datasets/. photos/ (159,9 МиБ) и backup/ (47,4 МиБ) оба учитывают зеркальные JPEG. |
| Unique | Allocated с учётом каждого inode жёсткой ссылки один раз; в таком дереве это соответствует du -s. | 942,2 МиБ. photos/ уменьшается до 112,7 МиБ, backup/ сохраняет 47,4 МиБ. |
| Files | Обычные файлы и символические ссылки. | 2356 файлов; лидирует projects/ с 1650 (70,0%). В одном node_modules/ — 1080 файлов. |

В Unique общий inode приписывается пути, который первым идёт при сортировке. Правило детерминировано, но может не совпасть с тем, какой путь вы считаете основным: `backup/` идёт раньше `photos/`, поэтому байты остаются за зеркалом, а размер оригиналов уменьшается. При нажатии `t` на две секунды появляется уведомление с названием метрики. Легенда sunburst при этом продолжает показывать байтовые доли.

     src="https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/metric-allocated.png" width="49%">
<img alt="Проводник в режиме Unique: home занимает 942,2 МиБ; photos/ уменьшился до 112,7 МиБ, а backup/ сохранил 47,4 МиБ."
     src="https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/metric-unique.png" width="49%">

*Слева Allocated: разреженный образ уменьшается до 96 МиБ. Справа Unique: уменьшается photos/, но не backup/.*

![Проводник в режиме Files: home содержит 2356 файлов, projects/ — 1650 (70,0%); в treemap преобладают node_modules (1080 файлов) и .venv (397 файлов).](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/metric-files.png)

## Подробности (F3)

Подробности — текстовое описание строки под курсором. На корне нашего примера:

![Панель Подробностей для /tmp/home: Logical ≥ 1,4 ГиБ (partial), Allocated ≥ 989,4 МиБ (partial), Unique on disk ≥ 942,2 МиБ (partial), Own Logical 16 Bytes, Own Allocated 4,0 КиБ, Files 2356, Subdirs 171, строка Policy, строка Access «Partial — 1 unreadable in this directory · 2 hidden at or below», время изменения и список Top Items.](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/explorer-details.png)

*Подробности для корня.*

- **Logical, Allocated и Unique on disk** имеют знак ≥ и пометку partial, потому что два дочерних каталога не удалось прочитать. Настоящий размер не меньше указанного.
- **Own …** учитывает только непосредственно этот каталог, не подкаталоги: 16-байтовую ссылку в Logical и собственный блок каталога 4 КиБ в Allocated/Unique.
- **Files и Subdirs** считают всё дерево ниже.
- **Policy** описывает границы сканирования: пересекались ли файловые системы, что исключено, максимальную глубину и запрет обхода ссылок.
- **Access** разделяет недоступность в этом каталоге и ниже: первый случай — `private/`, ещё два элемента скрыты в `projects/legacy/secrets/`.
- **Top Items** перечисляет самых крупных детей и их доли по активной метрике.

Для файла с жёсткими ссылками панель добавляет **Hard links** и **Unique owner** — путь, которому метрика Unique приписывает общие байты. В дереве дубликат помечен `[hardlink → …]`, а владелец — `[hardlink owner; 2 links]`.

## Различия между двумя снимками (d)

Когда для корня есть хотя бы два совместимых снимка (от монитора или `disktide scan --snapshot`), клавиша `d` включает сравнение. Сравниваются **два сохранённых снимка**, по умолчанию последние два; текущее сканирование не участвует.

Это видно по нескольким признакам. Индикатор показывает пару (например, `Diff snapshots #33 → #34`), при включении появляется уведомление, а размеры дерева соответствуют новому снимку. Поэтому `datasets/` здесь имеет размер 278,0 МиБ, тогда как мгновением раньше было 280,3 МиБ: четыре Parquet-файла изменились после создания снимка #34.

`[` и `]` переключают на более новую и старую пары; повторное нажатие `d` возвращает к текущему сканированию.

![Проводник в режиме Diff. Индикатор «Diff snapshots #33 → #34». В строках дерева дельты: datasets/ «≈ ▲ +6.0 MiB (+2.2%)», .cache/ «≈ ▼ -20.0 MiB (-19.3%)», downloads/ «≈ ＋ +16.0 MiB (+100.0%)», последняя строка «… remainder/». Sunburst окрашен по направлению: большая часть серая, datasets красная, .cache зелёная, downloads — узкий янтарный сектор, удалённые drafts — синий. В центре «home ≈ ▲ +1.0 MiB (+0.1%)». Семь выносок отмечают описанные части.](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/diff-sunburst.png)

*Режим Diff для самой новой пары снимков.*

1. **Пара:** базовый → целевой снимок.
2. **Рост:** `▲ +6.0 MiB (+2.2%)` — изменение и его доля относительно базового размера.
3. **Уменьшение:** `▼ -20.0 MiB (-19.3%)` — кэшированную модель удалили из `.cache/`.
4. **Новый путь:** `＋ +16.0 MiB (+100.0%)` — `downloads/` отсутствовал в снимке #33. Удалённый путь помечается `×`.
5. **`… remainder/`.** Показаны самые большие и сильнее всего изменившиеся пути; остальные суммируются в строки остатка. Поэтому сумма остаётся точной.
6. **Центр:** итоговое изменение корня.
7. **Легенда:** в Diff цвет означает направление, а не тип файла. В стандартной теме рост красный, уменьшение зелёное, новый путь янтарный, удалённый синий, без изменений — серый.

Каждая дельта начинается с `≈` — это оговорка о полноте. В нашем каталоге есть недоступные директории, поэтому каждый снимок неполный, а числа — нижняя оценка. Измеренное направление при этом сохраняется. Только путь, который сам был недоступен в одном из снимков, показывается как `≈ partial` без направления.

![Та же пара снимков в treemap. Рамки окрашены по общему направлению изменения: рамка home красная (рост), .cache и papers зелёные (уменьшение), downloads янтарный; неизменившиеся объекты вроде dev-box.qcow2 серые и подписаны «≈ · 0 Bytes (+0.0%)».](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/diff-treemap.png)

*Та же пара в treemap. Рамка каталога отражает его суммарное направление: `▼ .cache` и `▼ papers` уменьшились, `▲ datasets` вырос. Удалённый путь сохраняет небольшую площадь — максимум одну двадцатую корня, — поэтому не исчезает из диаграммы.*

## Центр мониторинга (2)

Монитор — сохранённое описание пути, интервала, метрики, политики сканирования и правила хранения истории. Центр мониторинга показывает историю.

Фоновой службы нет. Снимки создаются, только пока TUI собирает данные клавишей `S` или запущен обработчик `disktide watch`. Статус `enabled/no-host` означает, что монитор включён, но его никто не обслуживает. Автозапуск начинает сбор данных при будущих запусках TUI.

![Центр мониторинга. Слева список с «home enabled/no-host/unknown». Справа вкладка History: кнопка Start sampling; сводка «34 canonical point(s)», «Pair #33 → #34 · partial confidence»; легенда различий и метки динамики; вкладки Trend, Diff Map, Growth Rings и Heatmap. Временной график home постепенно растёт с 1167,7 МиБ до 1394,9 МиБ с 12 августа по 12 сентября 2026 года, с падением в начале сентября. В таблице истории строка 2026-09-04 помечена partial и pinned. Девять выносок указывают на описанные части.](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/monitor-trend.png)

*Вкладка History, вид Trend.*

1. **Список мониторов.** Состояние каждого записано как желаемое / активность / здоровье.
2. **`Start sampling [S]`** запускает обработчик для всех включённых мониторов в этом сеансе. Автозапуск запоминает этот выбор.
3. **Вкладки.** History, Details, Alerts и Retention; переходите между ними щелчком.
4. **Сводка.** Сначала состояние сбора и число точек, затем общая для графиков пара снимков и уровень доверия. Клавиши `b` и `v` на строке истории задают начало и конец сравнения, `l` возвращает к последней паре.
5. **Клавиши и метки.** Сначала легенда различий, затем знаки динамики: `*` оповещение или аномалия, `c` очистка, `~` неполная точка, `o` закреплена, `.` обычный замер.
6. **Вкладки графиков.** `F1`–`F4` или Tab для переключения.
7. **Точки.** Каждая соответствует снимку; знак показывает его тип.
8. **Оси.** Размер в МиБ и время. `z` показывает последние 50% или 25% истории; Shift+←/→ перемещает временное окно.
9. **Таблица истории.** Одна строка на снимок, с пометкой partial или pinned. `i` закрепляет выделенный снимок и защищает его от удаления по сроку хранения. Здесь закреплён последний снимок до удаления резервного tar-архива.

График показывает корень монитора. Если при нажатии `2` в Проводнике был выбран подкаталог, он становится второй линией (то же происходит при Enter на строке тепловой карты). Обе линии используют общую шкалу, поэтому небольшой каталог рядом с большим корнем может выглядеть почти плоским.

Чтобы увидеть характер изменения самого корня, сначала выберите корень, как на иллюстрации. Ступени соответствуют появлению CSV, фотографий и `node_modules/`; всплеск — появлению и удалению tar-архива; спад — очистке кэша pip перед его восстановлением.

### Тепловая карта (F4)

У тепловой карты другой вопрос: она показывает не самые крупные объекты и не последнее изменение, а **что продолжает расти**.

![Вкладка Heatmap: слева пути, в центре 16 столбцов интервалов, справа доля последовательного роста. tmp и tmp/build.log имеют единицу во всех 16 колонках, 100%, s16; у downloads и его файлов знаки ? и одна цифра в последнем интервале, 100%, s1; projects/thesis показывает 75%, s5; models — цифру каждые три колонки, 31%, s1. Внизу легенда и «+N more». Семь выносок описывают элементы.](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/monitor-heatmap.png)

*Тепловая карта для последних 16 интервалов.*

1. **Строки** — пути внутри корня монитора. Сначала они сортируются по доле интервалов с ростом, затем по самой длинной непрерывной серии роста и затем по величине роста.
2. **Столбцы** — до 16 интервалов между соседними снимками; самый новый — справа.
3. **Цифра** означает рост в интервале. Степень от 1 до 4 зависит от величины относительно крупнейшего изменения на карте. `tmp/build.log` рос во всех 16 интервалах.
4. **`?`** означает, что путь ещё не существовал. Всё содержимое `downloads/` появилось в последнем интервале.
5. **`·`** — интервал без изменений. `models/` растёт примерно каждые три дня.
6. **Consistency** — доля интервалов с ростом, учитываемая только после появления пути. `sN` — самая длинная непрерывная серия. Смотрите на оба значения: `downloads/` рос в единственном интервале (100%, s1), а `tmp/build.log` — во всех шестнадцати (100%, s16).
7. **Легенда** и число путей, не поместившихся в панели. `↑`/`↓` выбирают строку; Enter показывает её второй линией на графике Trend.

Уменьшение `▼`, удаление `×`, неполнота `≈` и несовместимость `!` обозначаются как в Diff. Ячейка из неполной пары рисуется тускло, но сохраняет направление изменения.

## Обзор файловых систем (3)

Обзор ФС не сканирует каталоги. Он перечисляет смонтированные файловые системы и блочные устройства компьютера: ёмкость, использование, тип хранилища и квоту. На общей машине это первое место, куда стоит заглянуть, если сканирование замедлилось или запись не удалась.

Три иллюстрации ниже показывают выдуманный сервер. Экран настоящий, но `tool/gen_blog_shots.py` подаёт ему фиксированные таблицы монтирования, устройств и квот, поэтому в публикацию не попадают сведения реального хоста. Вымышленный сервер имеет зашифрованный корневой NVMe, RAID из HDD с томами контейнеров, привязанными к нему, резервный диск btrfs, домашний и проектный NFS, временный Lustre, несколько snap-пакетов и новый ещё не отформатированный диск.

![Обзор ФС вымышленного сервера. Сводка: 21 файловая система, всего 34,7 ТиБ, занято 20,7 ТиБ (60%), восемь образов только для чтения, пять повторных монтирований свёрнуто. Полоса ёмкости показывает /, /backup, /data, /home, /projects, /scratch и «10 others». В таблице есть характеристики Flash · Encrypted, HDD · CoW · Compressed и HDD · RAID; заполнение /projects — 78%, /data — 91,4%; квота /home — 38,2 из 50,0 ГиБ; две свёрнутые строки. Ниже — дерево устройств NVMe, двух частей RAID, USB-диска и диска без формата; предупреждение сообщает, что у одного диска нет смонтированной файловой системы. Семь выносок указывают на описанные элементы.](https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/fs-overview.png)

*Обзор файловых систем вымышленного сервера.*

1. **Сводка.** Число монтирований, общая и занятая ёмкость, число свёрнутых строк и причина группировки.
2. **Полоса ёмкости.** Ширина каждой файловой системы пропорциональна её ёмкости. Цвет показывает тип хранилища: красный — сеть, оранжевый — вращающийся диск, зелёный — флеш-память или RAM. Файловые системы меньше 1% объединяются в `others`.
3. **Тип хранилища.** Сначала показывается носитель, затем его характеристики: `Encrypted` у корня LUKS, `RAID` у md-массива, `CoW · Compressed` у резервного btrfs-диска.
4. **Использование.** Занятое место делится на занятое плюс доступное (как вычисляет df), поэтому блоки, зарезервированные для root, не считаются свободными. Полоса становится оранжевой на 70% (`/projects`) и красной на 90% (`/data`). У образа только для чтения — обычная полоса: 100% заполнения здесь ожидаемо.
5. **Квота.** Использование и лимит пользователя, если команда quota их сообщает; в примере — домашний NFS.
6. **Блочные устройства.** Дерево lsblk показывает диски, разделы, участники RAID, зашифрованный том и точки монтирования. Если на диске нет ни одной смонтированной файловой системы, об этом сказано в заголовке; здесь это `sdd`.
7. **Свёрнутые строки.** Повторяющиеся записи собраны отдельно: восемь snap-образов и пять bind-монтирований томов контейнеров из `/data`, каждое из которых снова показывает весь размер `/data`. Клавиша `i` раскрывает список.

     src="https://raw.githubusercontent.com/williamqwu/assets/main/disktide/blog/fs-block-details.png" width="49%">

*Enter на монтировании (слева) или блочном устройстве (справа).*

Enter открывает подробности выбранной строки. Для монтирования это устройство, тип, класс скорости, свойства носителя, ёмкость и зарезервированные блоки, квота пользователя, если она есть, inode, размер блока и параметры монтирования. Для блочного устройства — модель диска, носитель и разделы.

`B` запускает проверку скорости выбранного монтирования. Сначала DiskTide показывает каталог, куда будет записан файл, и ещё раз запрашивает подтверждение. Если корень монтирования недоступен для записи, используется ваш каталог на этой же файловой системе. Тест записывает не более 256 МиБ и не более четверти доступного по квоте места. Если записываемого каталога нет, программа сообщает об этом и не меняет файловую систему.
